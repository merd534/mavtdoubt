# Neon Noir: Shadows of Rain

Процедурный нуарно-неоновый детектив на **Godot 4.6** (GDScript). Огромный
процедурный город, преступления генерируются ИИ, каждое дело гарантированно
раскрываемо.

Визуальный и структурный референс — изображения в папке `картинки/`.
Что именно из них взято, разобрано в [docs/CITY_REFERENCE.md](docs/CITY_REFERENCE.md).

## Быстрый запуск

Проверки Фазы 1 — конвейер дел:

```bash
godot --headless --path . res://scenes/dev/Phase1TestBench.tscn
```

Проверки Фазы 2 — генерация и стриминг города:

```bash
godot --headless --path . res://scenes/dev/Phase2CityBench.tscn
```

Код выхода `0` — всё зелёное, `1` — есть провалы. Отчёты пишутся в
`user://phase1_report.txt` и `user://phase2_report.txt`, дела — в
`user://last_case_*.json`, логи — в `user://logs/`.

Свободный полёт по городу (ЛКМ — захват мыши, WASD+QE, F — полёт/ходьба):

```bash
godot --path . res://scenes/dev/Phase2CityBench.tscn
```

Замер производительности облётом и снимки видов:

```bash
godot --path . res://scenes/dev/Phase2CityBench.tscn -- --flythrough
```

```bash
godot --path . res://scenes/dev/Phase2CityBench.tscn -- --screenshot
```

## Что реально работает в Фазе 1

**Город (`CityAtlas`)** — 4600 × 3400 м = **15.64 км²** (референс требует 8.7),
**17 районов**, **237 играбельных локаций** (референс: 120+), 16 именованных
landmark'ов с референсной панели POI, река с 4 подсвеченными мостами,
подземная сеть, ровно 15 убежищ. Каждая локация имеет адрес, число этажей,
уровень замка, наличие камеры и часы работы. Всё детерминировано по сиду.

**Жители (`Citizens`)** — 420 NPC с полным набором криминалистических признаков
(отпечаток, группа крови, рост, размер и тип обуви, цвет волос, леворукость,
татуировка, автомобиль с номером, личные вещи), работой, домом, расписанием
смен и симметричным графом социальных связей. Рост и размер обуви
скоррелированы, чтобы улики не выглядели абсурдно.

**LLM (`Api` + `CrimePromptBuilder` + `CrimeSchema`)** — запрос к
`https://models.inference.ai.azure.com/chat/completions`, модель `gpt-4.1`,
заголовок `Authorization: Bearer <token>`. Модель получает **закрытый мир**:
только реальные `citizen_id` и `location_id`, закрытые списки типов улик,
орудий, мотивов и допустимых атрибутов. Промпт автоматически сжимается под
лимит входа провайдера (8000 токенов) — иначе GitHub Models отвечает 413.

**Гарантия решаемости (`SolvabilityValidator`)** — главный предохранитель.
После него набор улик **всегда** сужает круг подозреваемых ровно до одного
человека — убийцы. Валидатор не просто проверяет, а ремонтирует:

* улика противоречит убийце → значение правится на фактическое;
* круг шире одного → добавляется улика с уникальным признаком;
* нет твёрдого доказательства → добавляется отпечаток;
* алиби убийцы «подтверждено» → переводится в `contradicted`;
* ложный след указывает на убийцу → убирается;
* цепочка решения пустая → строится жадным минимальным покрытием;
* в тексте всплыло имя убийцы → вырезается как спойлер.

**Оффлайн-режим (`FallbackCrimeGenerator`)** — если токена нет, сеть недоступна
или модель вернула мусор, дело собирается локально и проходит **те же**
валидаторы. Игра играбельна всегда.

## Что работает в Фазе 2

**Стриминг.** Мир 4600 × 3400 м режется на сетку 20 × 15 чанков по 240 м.
Вокруг наблюдателя держится круглое (не квадратное) кольцо радиусом по дальности
прорисовки. Сборка нарезана по кадрам: не больше `build_budget_ms` миллисекунд
и не больше `max_builds_per_frame` чанков за кадр, выгрузка — тоже с лимитом.
Без этих лимитов перелёт через город ронял кадр до 14 FPS на разовом
освобождении 69 чанков.

**Три уровня детализации.** Ближние чанки: реквизит, коллизии, настоящие
источники света, входы в здания. Средние: без реквизита и коллизий. Дальние:
только силуэты и дороги. Вывески и фонари живут на **всех** уровнях — это по
одной MultiMesh на чанк, зато именно они рисуют неоновый ковёр вдали.

**Дальнее поле.** За кольцом стриминга город не заканчивается: карта покрыта
супер-плитками по 960 м с грубым силуэтом (куб на квартал), которые включаются
через `visibility_range_begin` ровно там, где настоящие чанки уже выгружены.
Стоит до 20 дополнительных вызовов отрисовки на полный обзор.

**Бюджет отрисовки.** Чанк любой плотности стоит ~7 вызовов: 5 MultiMesh
(здания, вывески, реквизит, столбы фонарей, светящиеся головы) + 2 меша дорог.
Окклюдер — один `ArrayOccluder3D` на чанк вместо сотни боксов.
Замер облёта на 1600×900: средний **63 FPS**, 1% низких **28.8 FPS**,
худший кадр **37.6 мс** — и это на скорости 280 м/с, недостижимой в игре.

**Ноль текстур.** Весь вид даётся четырьмя процедурными шейдерами:
`facade` (окна, витрины первого этажа, подтёки дождя, размер окна в метрах
независимо от растяжения куба), `neon` (мерцание, бегущая строка, свечение
трубки), `road` (лужи, мокрый асфальт под SSR, янтарная разметка магистралей),
`water` (волны и круги от дождя).

**Интерьеры.** Строятся лениво для здания, к которому подошёл игрок, и
выгружаются при уходе (LRU на 4 подъезда). Внутри: подъезд, коридоры,
квартиры с мебелью, лестничные пролёты, шахта лифта с кабиной и вентиляция —
вертикальная шахта плюс короба под потолком коридора. Один интерьер стоит
5 вызовов отрисовки.

## Про отсутствие `try/catch`

В GDScript исключений не существует. Вместо них по всему коду применены:

* тип-результаты — `ApiJob.result`, `CrimeSchema.Report`, `SolvabilityValidator.Report`;
* guard-методы логгера — `Log.check()`, `Log.require()`, `Log.require_valid()`;
* приведение типов с фолбэком в `GameConfig._coerce()` — повреждённый `.cfg`
  не может уронить игру;
* защищённый разбор JSON — поиск сбалансированных скобок с учётом строк и
  экранирования, а не наивный `parse`;
* ветка деградации на каждом шаге конвейера.

## Настройка токена

Приоритет источников (см. `GameConfig.resolve_llm_token`):

1. переменная окружения `NOIR_LLM_TOKEN`
2. `res://secrets.cfg`
3. `user://secrets.cfg`
4. пусто → автоматический оффлайн-режим

> **Токен в `secrets.cfg` был передан в открытом виде и считается
> скомпрометированным.** Отзовите его на <https://github.com/settings/tokens>
> и впишите новый.

## Дальше

Фаза 2 опирается на уже готовые данные `CityAtlas`: `DISTRICT_TABLE` задаёт
плотность застройки, диапазоны высот, размер квартала и палитру каждого района;
`LANDMARK_TABLE` — точки, вокруг которых генератор обязан застраивать, а не
поверх; `fog_density_at()` — карту плотности тумана; `location_ids()` — 237
адресов, куда нужно поставить входы, лифты и обставленные комнаты.
